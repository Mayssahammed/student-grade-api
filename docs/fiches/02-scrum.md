# Fiche 2 : Scrum

## 1. Définition
Scrum est un cadre agile léger pour gérer le travail d'une équipe en cycles courts
appelés **sprints**, afin de livrer régulièrement un incrément de valeur (Schwaber &
Sutherland, 2020).

## 2. Éléments clés
| Catégorie | Éléments |
|---|---|
| Rôles | Product Owner, Scrum Master, Developers |
| Artefacts | Product Backlog, Sprint Backlog, Increment |
| Engagements | Product Goal, Sprint Goal, Definition of Done |
| Événements | Sprint, Sprint Planning, Daily Scrum, Sprint Review, Sprint Retrospective |

## 3. Idées clés
- Le Product Backlog est la liste ordonnée de tout ce qui peut améliorer le produit.
- Le sprint est une durée fixe (≤ 1 mois) produisant un incrément utilisable.
- La Definition of Done garantit un niveau de qualité partagé.
- L'inspection et l'adaptation sont régulières (revue et rétrospective).

## 4. Exemple Student Grade API
- Product Backlog : `docs/backlog.md`.
- Sprints : semaine 2 (itérations A et B), semaine 3 (analyse).

## 5. Lien avec l'adaptation
Scrum organise **quoi** faire et **quand** et permet de réorienter le produit à chaque sprint.

## 6. Limite essentielle
Scrum ne prescrit **aucune pratique technique**. Une équipe peut respecter tous les rituels
Scrum et accumuler des bugs et de la dette technique. C'est précisément la raison d'être de
ce sujet : « sans qualité, pas d'agilité ».
